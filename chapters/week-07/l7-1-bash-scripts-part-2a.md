# L7.1 - Bash scripts - Part 2A



# Advanced Shell Scripting

This lesson covers several powerful Bash features used in real-world shell scripting and programming:

- Debugging with `set -x`, `set +x`, and `bash -x`
- Combining conditions with `&&` and `||`
- Arithmetic using `(( ))`, `let`, `$(( ))`, `expr`, and `bc`
- Arithmetic operators
- Regex matching using `[[ string =~ regex ]]`
- String operations such as `substr`, `index`, and `length`
- Matching digits with regex
- Using `expr "$str" : "$regex"`
- Regular expressions such as `[oO]ctav[aeiou]*`
- Here documents (`heredoc`)
- Removing indentation with `<<-`
- Changing the `IFS` delimiter

---

# 1. Debugging Bash Scripts

When a shell script does not behave as expected, debugging is essential.

Suppose we have:

```bash
#!/bin/bash

name="Shubham"
age=27

echo "Name: $name"
echo "Age: $age"
```

Normally, running:

```bash
./script.sh
```

only shows the output:

```text
Name: Shubham
Age: 27
```

But sometimes we want to see **which commands Bash is actually executing**.

That is what shell tracing provides.

---

# 2. `set -x`

The command:

```bash
set -x
```

turns on execution tracing.

After `set -x`, Bash prints commands before executing them.

Example:

```bash
#!/bin/bash

set -x

name="Shubham"
age=27

echo "Name: $name"
echo "Age: $age"
```

Output may look like:

```text
+ name=Shubham
+ age=27
+ echo 'Name: Shubham'
Name: Shubham
+ echo 'Age: 27'
Age: 27
```

The lines beginning with:

```text
+
```

are debugging information generated by Bash.

---

# 3. Turning Debugging Off with `set +x`

To disable tracing:

```bash
set +x
```

Example:

```bash
#!/bin/bash

set -x

name="Shubham"
echo "Name: $name"

set +x

age=27
echo "Age: $age"
```

The commands before `set +x` are traced.

The commands after `set +x` are not traced.

---

# 4. Debug Only Part of a Script

You do not have to debug the entire script.

You can enable tracing around the suspicious section:

```bash
echo "Starting"

set -x

x=10
y=20
sum=$((x + y))
echo "$sum"

set +x

echo "Finished"
```

This is useful when a large script contains only one problematic section.

---

# 5. `bash -x script.sh`

Another way to enable debugging is:

```bash
bash -x ./script.sh
```

This runs the script with tracing enabled.

You do not need to modify the script.

Example:

```bash
bash -x script.sh
```

This is especially useful when you temporarily want to debug an existing script.

---

# 6. `set -x` vs `bash -x`

## Inside the script

```bash
set -x
```

Debugging begins at that point.

```bash
set +x
```

Debugging stops.

## From the command line

```bash
bash -x script.sh
```

The script runs with tracing enabled.

---

# 7. Practical Debugging Example

Consider:

```bash
#!/bin/bash

x=10
y=20

result=$((x + y))

echo "Result = $result"
```

Run:

```bash
bash -x script.sh
```

You may see:

```text
+ x=10
+ y=20
+ result=30
+ echo 'Result = 30'
Result = 30
```

Now you can see:

1. `x` was assigned `10`
2. `y` was assigned `20`
3. `result` became `30`
4. `echo` printed the result

This makes tracing extremely useful for finding incorrect variable values.

---

# 8. Combining Conditions with `&&` and `||`

Shell provides logical operators:

```text
&&
||
```

They can be used outside `[ ]` and also inside `[[ ]]`.

---

# 9. `&&` — AND / Run if Previous Command Succeeds

Example:

```bash
mkdir test && echo "Directory created"
```

The second command executes only if the first command succeeds.

Conceptually:

```text
command1 succeeds
        ↓
      && 
        ↓
command2 executes
```

Example:

```bash
[ -f file.txt ] && echo "File exists"
```

If `file.txt` exists, the message is printed.

---

# 10. `||` — OR / Run if Previous Command Fails

Example:

```bash
[ -f file.txt ] || echo "File does not exist"
```

If the file does not exist, the first command fails and the second command executes.

Conceptually:

```text
command1 fails
      ↓
     ||
      ↓
command2 executes
```

---

# 11. Combining `&&` and `||`

Example:

```bash
mkdir backup && echo "Created" || echo "Failed"
```

Meaning:

```text
If mkdir succeeds:
    print Created
otherwise:
    print Failed
```

This is a common shell idiom.

---

# 12. Conditions Inside `[[ ]]`

Bash's `[[ ]]` supports logical operators directly.

Example:

```bash
if [[ $age -ge 18 && $age -le 60 ]]; then
    echo "Eligible"
fi
```

This means:

```text
age >= 18 AND age <= 60
```

Another example:

```bash
if [[ $name == "Shubham" || $name == "Rahul" ]]; then
    echo "Name matched"
fi
```

Meaning:

```text
name is Shubham OR name is Rahul
```

---

# 13. `&&` Outside `[[ ]]` vs Inside `[[ ]]`

Outside:

```bash
command1 && command2
```

This is **command chaining**.

Inside:

```bash
[[ condition1 && condition2 ]]
```

This is **logical condition evaluation**.

Example:

```bash
[ -f file.txt ] && echo "exists"
```

Here `&&` connects two commands.

But:

```bash
[[ -f file.txt && -r file.txt ]]
```

checks two conditions inside one conditional expression.

---

# 14. Arithmetic in Bash

Bash provides several ways to perform arithmetic.

Important methods include:

```bash
(( ))
$(( ))
let
expr
bc
```

They are not all equivalent.

---

# 15. Arithmetic with `(( ))`

The arithmetic evaluation construct is:

```bash
(( expression ))
```

Example:

```bash
(( x = 10 + 20 ))
echo "$x"
```

Output:

```text
30
```

You can also write:

```bash
x=10
y=20

(( sum = x + y ))

echo "$sum"
```

Output:

```text
30
```

---

# 16. Incrementing with `(( ))`

A very common use is:

```bash
((x++))
```

Example:

```bash
x=10

((x++))

echo "$x"
```

Output:

```text
11
```

Other forms:

```bash
((x--))
((++x))
((--x))
```

---

# 17. `(( ))` in an `if`

The arithmetic expression itself can be used as a condition.

```bash
x=10

if (( x > 5 )); then
    echo "x is greater than 5"
fi
```

Output:

```text
x is greater than 5
```

This is cleaner than:

```bash
if [ "$x" -gt 5 ]; then
```

for integer arithmetic.

---

# 18. Important Property of `(( ))`

The exit status of:

```bash
(( expression ))
```

depends on the numerical result.

If the result is non-zero:

```text
exit status = 0
```

If the result is zero:

```text
exit status = 1
```

Therefore:

```bash
if (( x )); then
    echo "x is non-zero"
fi
```

works as a condition.

---

# 19. Arithmetic Operators in `(( ))`

Common arithmetic operators:

| Operator | Meaning |
|---|---|
| `+` | Addition |
| `-` | Subtraction |
| `*` | Multiplication |
| `/` | Integer division |
| `%` | Modulus/remainder |
| `**` | Exponentiation |
| `++` | Increment |
| `--` | Decrement |

Example:

```bash
a=10
b=3

echo $((a + b))
echo $((a - b))
echo $((a * b))
echo $((a / b))
echo $((a % b))
echo $((a ** b))
```

Output:

```text
13
7
30
3
1
1000
```

Notice:

```bash
10 / 3
```

produces:

```text
3
```

because Bash integer arithmetic does not produce a floating-point result.

---

# 20. Assignment Operators

`(( ))` supports compound assignment operators.

Examples:

```bash
((x += 5))
((x -= 2))
((x *= 3))
((x /= 2))
((x %= 2))
```

Example:

```bash
x=10

((x += 5))

echo "$x"
```

Output:

```text
15
```

---

# 21. Comparison Operators in `(( ))`

Inside `(( ))`, use arithmetic comparison operators:

```text
<
<=
>
>=
==
!=
```

Example:

```bash
a=10
b=20

if (( a < b )); then
    echo "a is smaller"
fi
```

Output:

```text
a is smaller
```

You do not need:

```bash
-lt
-gt
-eq
```

inside `(( ))`.

Those are commonly used with `[ ]`.

---

# 22. `let`

`let` is another Bash arithmetic facility.

Example:

```bash
let x=10+20
echo "$x"
```

Output:

```text
30
```

Another example:

```bash
x=10
y=20

let sum=x+y

echo "$sum"
```

Output:

```text
30
```

Increment:

```bash
let x++
```

However, modern Bash scripts generally prefer:

```bash
((x++))
```

over:

```bash
let x++
```

---

# 23. Arithmetic Expansion `$(( ))`

`$(( ))` is used when you want the arithmetic result as a value.

Example:

```bash
x=10
y=20

sum=$((x + y))

echo "$sum"
```

Output:

```text
30
```

You can directly print:

```bash
echo $((10 + 20))
```

Output:

```text
30
```

---

# 24. `(( ))` vs `$(( ))`

This distinction is very important.

### `(( ))`

Used for arithmetic evaluation.

```bash
((x = 10 + 20))
```

### `$(( ))`

Used for arithmetic expansion.

```bash
x=$((10 + 20))
```

Think:

```text
(( ))   → perform/evaluate arithmetic
$(( ))  → calculate and substitute the result
```

---

# 25. `expr`

`expr` is an older external command for performing arithmetic and string operations.

Example:

```bash
expr 10 + 20
```

Output:

```text
30
```

Important: spaces are required.

Correct:

```bash
expr 10 + 20
```

Incorrect:

```bash
expr 10+20
```

For modern Bash arithmetic, prefer:

```bash
echo $((10 + 20))
```

---

# 26. Arithmetic with `expr`

Example:

```bash
a=20
b=5

result=$(expr "$a" + "$b")

echo "$result"
```

Output:

```text
25
```

Multiplication requires escaping `*` because the shell may interpret it as a wildcard:

```bash
expr 10 \* 5
```

Output:

```text
50
```

---

# 27. `bc` — Bench Calculator

`bc` is a command-line calculator.

Unlike Bash integer arithmetic, `bc` can perform floating-point calculations.

Example:

```bash
echo "10 / 3" | bc
```

Output:

```text
3
```

By default, `bc` also performs integer-style division when `scale` is not specified.

---

# 28. Floating-Point Arithmetic with `bc`

Set the scale:

```bash
echo "scale=2; 10 / 3" | bc
```

Output:

```text
3.33
```

Another example:

```bash
echo "scale=4; 22 / 7" | bc
```

Output:

```text
3.1428
```

This is one major reason to use `bc`.

---

# 29. `bc` Interactive Mode

Run:

```bash
bc
```

Then:

```text
10 + 20
```

Output:

```text
30
```

Then:

```text
5 * 6
```

Output:

```text
30
```

Exit using:

```text
quit
```

or press:

```text
Ctrl-D
```

---

# 30. Bash Arithmetic vs `bc`

| Method | Integer | Floating Point |
|---|---:|---:|
| `(( ))` | Yes | No |
| `$(( ))` | Yes | No |
| `let` | Yes | No |
| `expr` | Yes | No |
| `bc` | Yes | Yes |

For normal integer calculations:

```bash
(( ))
```

is usually the preferred Bash-native approach.

For decimal calculations:

```bash
bc
```

is useful.

---

# 31. Regular Expressions in Bash

Bash supports regex matching using:

```bash
[[ string =~ regex ]]
```

The operator:

```bash
=~
```

means:

> Does the left-hand string match the regular expression on the right?

---

# 32. Basic `=~` Example

```bash
str="hello123"

if [[ $str =~ [0-9]+ ]]; then
    echo "Contains digits"
fi
```

Output:

```text
Contains digits
```

The regex:

```regex
[0-9]+
```

means:

```text
one or more digits
```

---

# 33. Match an Entire String

Suppose we want a string containing **only digits**.

Use:

```regex
^[0-9]+$
```

Meaning:

```text
^       beginning of string
[0-9]   any digit
+       one or more
$       end of string
```

Example:

```bash
str="12345"

if [[ $str =~ ^[0-9]+$ ]]; then
    echo "Only digits"
else
    echo "Not only digits"
fi
```

Output:

```text
Only digits
```

---

# 34. Why `^` and `$` Matter

Without anchors:

```bash
[[ $str =~ [0-9]+ ]]
```

this can match a substring.

For example:

```text
abc123xyz
```

contains digits.

But if we want the **entire string** to consist only of digits:

```bash
[[ $str =~ ^[0-9]+$ ]]
```

Now:

```text
12345
```

matches.

But:

```text
abc123
```

does not.

And:

```text
123abc
```

does not.

---

# 35. Regex Examples with `=~`

```bash
str="hello"

[[ $str =~ ^hello$ ]]
```

Matches.

Another:

```bash
str="abc123"

[[ $str =~ ^[a-z]+[0-9]+$ ]]
```

Matches because the string contains:

```text
lowercase letters + digits
```

Examples:

```text
abc123    → match
hello42   → match
ABC123    → no match
abc       → no match
123abc    → no match
```

---

# 36. `=~` Returns an Exit Status

Example:

```bash
if [[ $str =~ regex ]]; then
    echo "Matched"
else
    echo "Did not match"
fi
```

If the regex matches:

```text
exit status = 0
```

If it does not:

```text
exit status = 1
```

This is why `=~` works naturally inside `if`.

---

# 37. Regex Capture with `BASH_REMATCH`

Bash stores regex matches in:

```bash
BASH_REMATCH
```

Example:

```bash
str="abc123"

if [[ $str =~ ([a-z]+)([0-9]+) ]]; then
    echo "Entire match: ${BASH_REMATCH[0]}"
    echo "Letters: ${BASH_REMATCH[1]}"
    echo "Digits: ${BASH_REMATCH[2]}"
fi
```

Output:

```text
Entire match: abc123
Letters: abc
Digits: 123
```

Important:

```text
BASH_REMATCH[0] → complete match
BASH_REMATCH[1] → first capture group
BASH_REMATCH[2] → second capture group
```

---

# 38. String Functions: `substr`, `index`, `length`

The commands:

```text
substr
index
length
```

are commonly associated with **AWK**, not Bash.

They operate on strings.

---

# 39. `substr(str, start, length)`

Syntax:

```awk
substr(str, start, length)
```

It extracts a substring.

Example:

```bash
echo 'BEGIN { print substr("abcdef", 2, 3) }' | awk
```

Output:

```text
bcd
```

AWK uses **1-based indexing**.

Therefore:

```text
abcdef
123456
```

Position `2` is:

```text
b
```

---

# 40. `substr(str, start)`

The length argument can be omitted.

```awk
substr(str, start)
```

Example:

```bash
awk 'BEGIN {
    print substr("abcdef", 3)
}'
```

Output:

```text
cdef
```

Meaning:

```text
start at position 3
take everything until the end
```

---

# 41. `index(str, char)`

`index()` returns the position of the **first occurrence** of a substring.

Syntax:

```awk
index(str, search)
```

Example:

```bash
awk 'BEGIN {
    print index("hello", "l")
}'
```

Output:

```text
3
```

Because:

```text
hello
12345
```

The first `l` is at position `3`.

---

# 42. `index()` with a Character That Does Not Exist

Example:

```bash
awk 'BEGIN {
    print index("hello", "x")
}'
```

Output:

```text
0
```

So:

```text
0 → not found
positive number → position of first occurrence
```

---

# 43. `length(str)`

`length()` returns the number of characters in a string.

Example:

```bash
awk 'BEGIN {
    print length("hello")
}'
```

Output:

```text
5
```

Another:

```bash
awk 'BEGIN {
    str="Shubham"
    print length(str)
}'
```

Output:

```text
7
```

---

# 44. Summary of AWK String Functions

| Function | Purpose |
|---|---|
| `substr(str,start,length)` | Extract substring |
| `index(str,search)` | Find first occurrence |
| `length(str)` | Find string length |

Remember that these are **AWK functions**.

---

# 45. Regex: Match Only Digits

A common exam question is:

> Write a regex that matches a line containing only digits.

Answer:

```regex
^[0-9]+$
```

Explanation:

```text
^       start of line/string
[0-9]   digit
+       one or more digits
$       end of line/string
```

Matches:

```text
123
987654
0
42
```

Does not match:

```text
abc
123abc
abc123
12.5
-123
12 34
```

---

# 46. Testing Digit Regex with `grep`

Using:

```bash
grep -E '^[0-9]+$' file.txt
```

Example file:

```text
123
hello
456
abc123
789
```

Run:

```bash
grep -E '^[0-9]+$' file.txt
```

Output:

```text
123
456
789
```

---

# 47. Testing Digit Regex with Bash

```bash
while IFS= read -r line; do
    if [[ $line =~ ^[0-9]+$ ]]; then
        echo "$line is numeric"
    else
        echo "$line is not numeric"
    fi
done < file.txt
```

This is useful when processing input line by line.

---

# 48. Regex `[oO]ctav[aeiou]*`

Consider:

```regex
[oO]ctav[aeiou]*
```

Let's break it down.

```text
[oO]
```

matches:

```text
o
O
```

Then:

```text
ctav
```

must occur literally.

Then:

```text
[aeiou]*
```

means:

> zero or more vowels

So the regex can match strings such as:

```text
Octav
octav
Octave
octavi
Octavio
octavia
```

---

# 49. Understanding `[aeiou]*`

The expression:

```regex
[aeiou]*
```

means:

```text
zero or more vowels
```

The `*` is important.

Because it means zero or more, this matches:

```text
Octav
```

The vowel portion can be empty.

It also matches:

```text
Octave
Octavio
Octavia
```

because the ending contains vowels.

---

# 50. Test `[oO]ctav[aeiou]*`

Using Bash:

```bash
str="Octavio"

if [[ $str =~ [oO]ctav[aeiou]* ]]; then
    echo "Matched"
fi
```

Output:

```text
Matched
```

Another:

```bash
str="octave"

if [[ $str =~ [oO]ctav[aeiou]* ]]; then
    echo "Matched"
fi
```

Output:

```text
Matched
```

---

# 51. Important: Regex Matching Can Match a Substring

Consider:

```bash
str="helloOctavio123"
```

This:

```bash
[[ $str =~ [oO]ctav[aeiou]* ]]
```

can match the `Octavio` portion.

If you want the **entire string** to match the pattern, use anchors:

```bash
[[ $str =~ ^[oO]ctav[aeiou]*$ ]]
```

Now the entire string must match.

---

# 52. `expr "$str" : "$regex"`

`expr` also supports regular expression matching using:

```bash
expr "$str" : "$regex"
```

Example:

```bash
str="12345"

expr "$str" : '^[0-9]*'
```

Output:

```text
5
```

The result is the length of the matching portion.

---

# 53. `expr` Regex Matching

The syntax:

```bash
expr "$str" : "$regex"
```

checks the regex starting at the beginning of the string.

Example:

```bash
str="hello123"

expr "$str" : '^[a-z]*'
```

Output:

```text
5
```

Because:

```text
hello
```

contains five lowercase letters at the beginning.

---

# 54. `expr` Regex and `^`

For example:

```bash
str="abc123"

expr "$str" : '[a-z]*'
```

returns the length of the initial matching portion.

A common pattern is:

```bash
expr "$str" : '^[0-9]*$'
```

However, remember that `expr` regex syntax differs from Bash's `[[ =~ ]]` in some details.

For modern Bash scripts, prefer:

```bash
[[ $str =~ regex ]]
```

when possible.

---

# 55. `expr` Can Also Extract with `\(...\)`

Historically, `expr` supports capture-style extraction.

Example:

```bash
str="abc123"

expr "$str" : '\([a-z]*\)'
```

The exact behavior depends on the regular expression and `expr` implementation.

For modern Bash scripting, using:

```bash
[[ $str =~ regex ]]
```

with:

```bash
BASH_REMATCH
```

is usually clearer.

---

# 56. Here Document — Heredoc

A **here document** allows us to provide multiple lines of input directly to a command.

Basic syntax:

```bash
command <<EOF
text
text
text
EOF
```

The delimiter can be any word.

Commonly:

```text
EOF
```

is used.

---

# 57. Basic Heredoc Example

```bash
cat <<EOF
Hello
Welcome to Bash
This is a heredoc
EOF
```

Output:

```text
Hello
Welcome to Bash
This is a heredoc
```

The first `EOF` starts the heredoc.

The final `EOF` ends it.

---

# 58. Heredoc Mental Model

Think of:

```bash
cat <<EOF
hello
world
EOF
```

as:

```text
Send these lines to cat as standard input.
```

Conceptually:

```text
script
  |
  | heredoc input
  v
cat
```

---

# 59. Heredoc with Variables

Variables are expanded in a normal heredoc.

Example:

```bash
name="Shubham"

cat <<EOF
Hello $name
Welcome to Linux
EOF
```

Output:

```text
Hello Shubham
Welcome to Linux
```

The shell expands:

```bash
$name
```

before sending the text to `cat`.

---

# 60. Command Substitution in Heredoc

Command substitution also works.

```bash
cat <<EOF
Current user: $USER
Current directory: $(pwd)
Current date: $(date)
EOF
```

The shell evaluates the variables and commands.

---

# 61. Quoted Heredoc Delimiter

You can prevent expansion by quoting the delimiter:

```bash
cat <<'EOF'
Hello $USER
Directory: $(pwd)
EOF
```

Output contains the literal text:

```text
Hello $USER
Directory: $(pwd)
```

The quotes around:

```text
'EOF'
```

prevent parameter expansion, command substitution, and other shell expansions inside the heredoc body.

---

# 62. Heredoc for Creating Files

A very common use is generating configuration files.

```bash
cat <<EOF > config.txt
name=Shubham
language=Bash
shell=/bin/bash
EOF
```

Now:

```bash
cat config.txt
```

Output:

```text
name=Shubham
language=Bash
shell=/bin/bash
```

---

# 63. Heredoc with Commands

Heredocs can provide input to commands that normally expect standard input.

Example:

```bash
bc <<EOF
10 + 20
30 * 2
EOF
```

Output:

```text
30
60
```

---

# 64. `<<-` — Ignoring Leading Tabs

Sometimes heredocs are inside an indented script.

For example:

```bash
if true; then
    cat <<EOF
Hello
World
EOF
fi
```

Indentation can make the script harder to read.

Bash provides:

```bash
<<-
```

The `-` tells the shell to remove **leading TAB characters** from heredoc lines and the delimiter.

---

# 65. Example of `<<-`

```bash
if true; then
	cat <<-EOF
		Hello
		World
	EOF
fi
```

Here the indentation uses **TAB characters**.

Bash strips the leading tabs.

Output:

```text
Hello
World
```

---

# 66. Important `<<-` Rule

`<<-` removes leading:

```text
TAB
```

characters.

It does **not** generally remove ordinary spaces.

This is an important exam/troubleshooting point.

If you use spaces instead of tabs:

```bash
    Hello
```

the spaces will not be removed by:

```bash
<<-
```

---

# 67. Heredoc Delimiter Rules

The ending delimiter must appear correctly.

For example:

```bash
cat <<EOF
Hello
EOF
```

The final:

```text
EOF
```

must be recognized as the delimiter.

Do not accidentally write:

```text
EOF   
```

with extra content after it.

With `<<-`, leading tabs before the delimiter can be stripped.

---

# 68. IFS — Internal Field Separator

`IFS` stands for:

> Internal Field Separator

It controls how Bash splits words during certain operations such as:

- word splitting
- `read`
- some `for` loops
- splitting command output

By default, `IFS` commonly contains:

```text
space
tab
newline
```

---

# 69. Default IFS Example

Suppose:

```bash
str="apple banana orange"
```

Then:

```bash
for item in $str; do
    echo "$item"
done
```

Output:

```text
apple
banana
orange
```

The spaces separate the words.

---

# 70. Changing IFS

Suppose the data uses `:` as the delimiter:

```text
apple:banana:orange
```

Set:

```bash
IFS=:
```

Then:

```bash
str="apple:banana:orange"

IFS=:

for item in $str; do
    echo "$item"
done
```

Output:

```text
apple
banana
orange
```

---

# 71. `IFS=:` with `read`

A very common pattern is:

```bash
IFS=: read -r a b c <<< "apple:banana:orange"
```

Then:

```bash
echo "$a"
echo "$b"
echo "$c"
```

Output:

```text
apple
banana
orange
```

Here:

```text
IFS=:
```

tells `read` to use `:` as the separator.

---

# 72. Processing Colon-Separated Data

Linux files often contain colon-separated data.

For example, `/etc/passwd` uses:

```text
username:password:UID:GID:GECOS:home:shell
```

We can process a line like:

```bash
line="shubham:x:1000:1000:Shubham:/home/shubham:/bin/bash"

IFS=: read -r username password uid gid gecos home shell <<< "$line"

echo "Username: $username"
echo "UID: $uid"
echo "Home: $home"
echo "Shell: $shell"
```

Output:

```text
Username: shubham
UID: 1000
Home: /home/shubham
Shell: /bin/bash
```

---

# 73. Why `IFS=:` Is Useful

Suppose you have:

```text
one:two:three:four
```

Without changing `IFS`, Bash normally does not treat `:` as the default field separator.

By using:

```bash
IFS=:
```

we tell Bash:

```text
Use colon as the field separator.
```

---

# 74. Temporary IFS

Instead of permanently changing `IFS`, it is often safer to set it only for one command.

Example:

```bash
IFS=: read -r a b c <<< "one:two:three"
```

The `IFS=:` applies to that `read` command.

This avoids unintentionally affecting later parts of the script.

---

# 75. `IFS` and `for` Loops

Example:

```bash
data="red:green:blue"

IFS=:

for color in $data; do
    echo "$color"
done
```

Output:

```text
red
green
blue
```

The colon becomes the separator.

---

# 76. Important IFS Warning

Be careful with:

```bash
for item in $data
```

because unquoted expansion causes word splitting and pathname expansion.

For controlled simple data, it may be fine.

For robust scripts, prefer explicit parsing methods such as:

```bash
IFS=: read -ra fields <<< "$data"
```

or:

```bash
while IFS=: read -r field1 field2 field3; do
    ...
done
```

---

# 77. `IFS` with `read` — Important Pattern

For a colon-separated file:

```bash
while IFS=: read -r username password uid gid rest; do
    echo "$username -> $uid"
done < /etc/passwd
```

Here:

```bash
IFS=:
```

tells `read` to split each line on `:`.

The:

```bash
-r
```

prevents backslash interpretation.

This is a very useful Bash pattern.

Let's combine:

- `set -x`

- arithmetic
- regex
- `IFS`
- `read`

# 86. Common Mistakes

## Mistake 1 — Forgetting quotes with `expr`

Incorrect:

```bash
expr $str : $regex
```

Prefer:

```bash
expr "$str" : "$regex"
```

---

## Mistake 2 — Using `=` instead of `=~`

Regex matching in Bash:

```bash
[[ $str =~ regex ]]
```

Not:

```bash
[[ $str = regex ]]
```

`=` performs string/pattern comparison, while `=~` performs regex matching.

---

## Mistake 3 — Forgetting anchors

If the requirement is:

> entire string must contain only digits

use:

```regex
^[0-9]+$
```

not merely:

```regex
[0-9]+
```

---

## Mistake 4 — Expecting Bash arithmetic to handle decimals

This:

```bash
echo $((10 / 3))
```

produces:

```text
3
```

For decimal arithmetic:

```bash
echo "scale=2; 10/3" | bc
```

produces:

```text
3.33
```

---

## Mistake 5 — Using spaces with `<<-`

`<<-` removes leading **tabs**, not normal spaces.

---

## Mistake 6 — Permanently changing IFS unnecessarily

Instead of:

```bash
IFS=:
```

for the entire script, often prefer:

```bash
IFS=: read -r a b c <<< "$line"
```

This limits the effect.

# 90. Final Mental Model

Keep these concepts separate:

```text
DEBUGGING
    set -x
    set +x
    bash -x script.sh

COMMAND LOGIC
    &&
    ||

BASH CONDITIONS
    [[ ... ]]

BASH REGEX
    [[ $str =~ regex ]]

ARITHMETIC
    (( ... ))
    $(( ... ))
    let
    expr
    bc

AWK STRING FUNCTIONS
    substr()
    index()
    length()

HEREDOC
    <<EOF
    <<'EOF'
    <<-EOF

FIELD SPLITTING
    IFS
```

The most important distinctions to remember are:

```text
(( ))      → arithmetic evaluation
$(( ))     → arithmetic expansion

[[ =~ ]]   → Bash regular-expression matching

expr :     → older regex/string operation

substr()   → extract part of an AWK string
index()    → first occurrence position
length()   → string length

<<EOF      → heredoc
<<'EOF'    → heredoc without expansion
<<-EOF     → heredoc with leading TABs ignored

IFS=:      → use : as a field separator

set -x     → turn tracing ON
set +x     → turn tracing OFF
bash -x    → run a script with tracing
```
